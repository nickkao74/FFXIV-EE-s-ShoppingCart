# EE的FFXIV購物車

FFXIV 典禮系列（IL 740）的訂單與素材彙整工具。原本是純靜態網頁，現在改成**有後端的線上版**：
點單者把購物車直接送出，EE 在同一個列表看到所有訂單與素材缺口。

## 本機開發 / 測試

需要 Node.js 22 以上。後端是 Cloudflare Workers + D1，用 wrangler 在本機跑，
資料庫也是本機的 SQLite 檔（放在 `.wrangler/`），不會碰到正式環境的資料。

```bash
npm install
```

```bash
cp .dev.vars.example .dev.vars
```

```bash
npm run db:init
```

```bash
npm run dev
```

開 <http://localhost:8787>。

### 繞過 Discord 登入

`.dev.vars` 裡的 `DEV_LOGIN=1` 會開啟一條假登入路由 `/api/auth/dev`，
直接簽一張正常的 session cookie 給你，之後所有 API 都當你是真的登入過。

最簡單的用法：在登入畫面上按「以『點單者』測試」或「以『EE』測試」按鈕
（只有 localhost 才會顯示）。也可以直接開網址指定身分：

```
http://localhost:8787/api/auth/dev?role=member
http://localhost:8787/api/auth/dev?role=admin&name=測試用EE
```

參數：`role`（`member` / `admin`，預設 `member`）、`name`（顯示名稱）、`id`（Discord user id）。

**為什麼不會影響正式環境：**

- `DEV_LOGIN` 只寫在 `.dev.vars`。這個檔案已加入 `.gitignore`，
  而且 `wrangler deploy` 根本不讀它 —— 正式環境不會有這個變數。
- 路由本身另外檢查請求主機必須是 `localhost` / `127.0.0.1`。
- 兩個條件任一不滿足就回 **404**，跟這條路由不存在完全一樣。
- 產生的 session 跟 Discord 登入產生的是同一種格式、同一組 `SESSION_SECRET` 簽章，
  所以 cookie 只在本機有效，拿到正式站上驗不過。

要驗證正式環境確實關著，部署後開 `https://<你的網域>/api/auth/dev` 應該看到 404。

### 重置本機資料

```bash
npm run db:reset
```

正式環境第一次建表（只需要做一次）：

```bash

```

## 頁面

| 頁面 | 用途 |
| --- | --- |
| `index.html` | 入口頁，選身分；下方是「最近動態」（誰下單、誰的訂單完成、誰被刪單） |
| `order.html` | 點單者的裝備清單。進來就會先問暱稱（記在這台裝置上） |
| `order-cart.html` | 購物車：確認裝備、勾選自備素材、神典石估算、**送出訂單** |
| `ee-orders.html` | **EE 列表**：所有訂單、訂單總計、素材總計長條圖、持有素材輸入 |
| `ee-stock.html` | **素材庫存維護**：完整素材清單，盤點手上實際有多少（與 EE 列表共用同一份庫存） |
| `ee.html` | EE 原本的裝備清單工具 |
| `ee-materials.html` | EE 原本的個人素材總計（本機購物車，沒有掛在導覽列上，可直接開網址） |

### EE 列表的素材長條

每一項素材的長條分成三段，加起來就是這項素材的總需求量：

- 🔵 **訂單者自備** —— 下訂者在購物車勾了「我會自備」的部分
- 🟢 **目前已有** —— EE 自己在右邊欄位輸入的持有數量（即時存到後端）
- 🔴 **尚缺** —— 還要去收的量

**已完成的訂單不會計入**任何總計。

每張訂單卡片左上角有核取方塊，取消勾選就把那張訂單從素材總計與訂單總計裡拿掉（卡片還是留在列表上，
方便再勾回來），適合用來試算「先不做這張的話還缺什麼」。訂單面板右上角的「全部顯示」可以一鍵還原。
這個勾選是 EE 自己的檢視偏好，只記在這台裝置上，不會影響別人看到的東西。

### 製作素材與子素材

製作素材（銳鈦塊、菱錳石、鋒齒獸革、不飛鳥毛布、破布木木材）需要**兩種子素材，兩種都要**
—— 例如 1 個菱錳石 ＝ 玫瑰紅紋石原石 ×4 ＋ 新生王國研磨劑 ×2。不是二選一。

所以 EE 列表把子素材列在製作素材底下，各自獨立統計：訂購者常常只提供其中一種
（例如只給神典石換的新生王國研磨劑，不給採集的玫瑰紅紋石原石），這樣才看得出來哪一邊還缺。

- **製作素材那一列**的「已有」＝ 已經做好的成品數量
- **子素材那幾列**的需求量會自動扣掉已經做好的份 —— 做好 3 個菱錳石就代表那 3 份原料已經用掉了
- **「✔ 已補齊 & 製作」按鈕**：把還沒做的份量一次做完 —— 不足的子素材視為已補齊，
  從手上的子素材扣掉對應消耗量，成品數量補到需求量。按之前會先跳出確認，列出會消耗什麼

### 素材庫存

`ee-stock.html` 和 EE 列表右邊的數字欄位改的是**同一份庫存**（存在後端的 `stock`），
差別只在用途：EE 列表是邊看訂單缺口邊調，庫存頁是列出整個系列會用到的所有素材做完整盤點。

庫存頁有搜尋、「只看目前訂單需要的」篩選，以及 −/+ 快速加減；打字停手 0.5 秒自動存檔，
右上角會顯示「儲存中… / 已儲存 ✓」。

## 資料

全部存在 `server/db.json`（首次啟動自動建立，已加入 `.gitignore`）。
要清空重來，把這個檔案刪掉再重啟即可 —— 注意這也會換掉登入用的 secret，所有人要重新輸入一次密碼。

備份就是複製這個檔案。

## API

除了 `/api/login` 和 `/api/session`，其餘都要帶 `x-auth: <token>` 標頭。

| 方法 | 路徑 | 說明 |
| --- | --- | --- |
| POST | `/api/login` | `{password}` → `{token}` |
| GET | `/api/session` | token 是否還有效 |
| GET | `/api/state` | 訂單 + 持有素材 + 動態，一次抓齊 |
| GET/POST | `/api/orders` | 列出 / 新增訂單 |
| DELETE | `/api/orders/:id` | 刪單 |
| POST | `/api/orders/:id/complete` | 標記完成 |
| POST | `/api/orders/:id/reopen` | 取消完成 |
| GET/PATCH/PUT | `/api/stock` | EE 的持有素材（PATCH 是部分更新） |
| GET | `/api/events` | 入口頁的動態紀錄（最近 200 筆） |
